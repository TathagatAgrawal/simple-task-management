Tasks on a phone

Every phone below is a working mockup, not a picture: tap, swipe, hold and type. The layout keeps the desktop app's look (the same green, the same cards, chips and avatars) but behaves like an iPhone app: tabs at the bottom, a large title that collapses, swipe actions on rows, bottom sheets, action sheets and a context menu. Nothing here saves anywhere; each phone has its own pretend data (today is Sun 15 Nov 2026).

Same app, one screen at a time

The desktop shows the summary strip and all three columns together. A phone shows one thing at a time, so they become tabs and a segmented control.

Thumb first

Primary actions sit at the bottom or top-right, rows are at least 44 px tall, and anything destructive asks first in an action sheet.

Drag-and-drop becomes swipe

Dragging a card between columns doesn't work well on a phone. Swipe a row, hold it for a menu, or use the Status control inside the task.

Still saves as you go

No Save button anywhere, exactly like the desktop task drawer: each field saves when you leave it, and every change still lands in the task's updates.

Try it

This is the full app on one phone. Use the mouse like a finger: click to tap, click-and-drag a card sideways to swipe it, press and hold to open the quick menu.

Things to try

  • Swipe a card right to move it on (Start → Done). Swipe left for More and Delete.
  • Press and hold a card for a quick menu, like long-press on iOS.
  • Tap My tasks ⌄ to switch between yours, everyone's, unassigned, or one person's.
  • Mark GSTR-3B as done: a toast offers Undo, and because it repeats monthly, the next one is created.
  • Tap a card, then tap Due for the inline calendar, or Assignees to pick people.
  • Write an update at the bottom of a task; the keyboard pushes the composer up.
  • Tap + to add a task in a bottom sheet. Me has theme, password, people and sign out.

Building it without bloating the app

A suggestion, in line with “keep it simple”. None of this is built yet.

Recommended approach

  • One responsive page, not a second app: a max-width: 640px block in app.css restyles the same templates (_board.html, _summary.html, _panel.html). No new dependency or build step.
  • No new routes or SQL. The tabs and segmented control only change which fragment is visible; swipe calls the existing move endpoint and returns 204 with HX-Trigger: tasks-changed.
  • About 100 more lines in board.js: swipe and long-press on cards, tab and segment switching, sheet behaviour. The drawer <dialog> becomes a full-screen page on narrow widths.
  • Inputs at 16 px (so iOS doesn't zoom), safe-area padding via env(safe-area-inset-*), viewport-fit=cover, and a home-screen icon so it can be added to the Home Screen.

Small additions beyond the desktop app

  • Undo toast after moving a task (desktop has none). Optional.
  • Tab badge with the overdue count. Optional.
  • Pull-to-refresh, which only replaces the 60-second poll on a phone.
  • Remembered last tab and filter, like the filter is already remembered per browser.

Not included on purpose

  • No push notifications, offline mode or native app; they'd need a background service, which the philosophy doc rules out.
  • No edge-swipe-back gesture in these mockups (use the Back button); on a real iPhone, Safari provides it.
  • The /help manual stays a separate page, opened from Me.
